---

주제와 메모에서 독자가 답을 얻어야 할 질문을 정한다. 사용자 관점과 초안의 핵심 주장을 살리고, 비슷한 기존 글과 태그를 확인한다.

- 공식 문서, 릴리스 노트, 원 논문, 프로젝트 소스 등 주제에 맞는 자료를 직접 열어 핵심 주장과 예제를 확인한다. 버전에 따라 달라지는 내용은 적용 범위를 명시하고, 근거 링크는 해당 설명 가까이에 둔다. 확인하지 못한 수치나 저자의 실무 경험을 지어내지 않는다.
- 조사 결과를 바탕으로 문제 상황, 선택 이유, 독자가 시도할 구체적인 예를 자연스러운 한국어로 연결해 완성된 글을 쓴다. 메모와 자료가 충돌하면 근거에 따라 바로잡고 작성 결과에 알린다.
- 저장소 루트의 packages/posts/TEMPLATE.md 형식에 맞춰 title, date, tags, summary를 채운다. 날짜는 지정일 또는 작성일을 사용한다. 기존 대표 태그를 우선하고 파일명은 URL로 쓸 고유한 슬러그로 정한다. 기본 위치는 posts/<slug>.md이며 이미지가 있으면 posts/<slug>/index.md 옆에 두고 ./파일명으로 참조한다. 기존 글을 수정할 때는 주소를 유지한다.
- packages/posts/POST_PROCESS_GUIDE.md에 따라 본문의 컴포넌트명과 코드 블록을 확인하고, 링크와 로컬 이미지 경로를 점검한다. pnpm build로 정적 출력을 확인한다. 사용자에게 작성한 파일, 주요 근거, 검증 결과를 전달한다. 커밋·배포는 요청이 있을 때 수행한다.
